# Progressive identity-link importer (local validation build)

Rush and Breakthrough now use `progressive_builder.gd`. Conquest and other
modes retain their existing build path. No release is implied by this change.

## Data and behavior

`data/progressive_links.json` inside the addon packages derived full
partition-and-instance identities, standard-layout selection, sector sequence,
runtime-filtered objective sequence, membership edges, attachment pins, and
authored HQ property evidence. It is
generated by `tools/export_progressive_links.py` from the research reports;
there are no map-specific nearest-point corrections.

The standard-layout sequence is conditional on the normal launch assumptions
in the research manifest. These conditions and its non-live-verified status
are retained on the generated root. Static membership is not runtime activation.

- Sector selection no longer uses GEM root sorting or MCOM-count truncation.
- HQ, capture and MCOM membership follows the selected graph. Capture/MCOM
  order and local/cumulative objective IDs follow the verified native runtime
  filtering path rather than GUID, scene-tree, or position sorting.
- Spawn and polygon links use explicit pins and full identities.
- Shared targets are instantiated once. Single-owner spawns are parented under
  their controller; shared spawns retain multiple inspector references.
- HQArea, CaptureArea, SectorArea and all four retreat/advance area roles remain
  separate. No generic surrounding CombatArea is inferred from these polygons.
- Selected vehicles retain their class and exact membership. Where exactly one
  authored HQ owns the vehicle, its authored Team selects the class's faction
  model. This is labeled an authored-default preview, not live activation.
  Shared or conflicting ownership does not arbitrarily select a faction.
- Authored HQ Team/AltTeam values are imported with evidence metadata. For the
  mounted standard Rush/Breakthrough path, the verified authored baseline is
  Team 1 attacking, Team 2 defending, with `InvertedHQ`, `InvertTeamRoles`, and
  `GameModeControlsHQ` false. External playlist/Portal overrides remain outside
  that claim. The package also carries the exact shared-sector HQ activation
  table: Team 1 is active for Contested, Pre-Contested, Captured, Outcome,
  CleanUp and Secured; Team 2 for Contested, Next, Prepare, Pre-Contested and
  Secured. Duplicate team slots do not receive duplicate template IDs.
- SDK vehicle skins, selected resupply/AA placements, deploy cameras and explicit
  carrier preview paths retain their existing rendering helpers.

## Template compatibility and limits

Sector boundary wrappers, object IDs, local objective naming and Breakthrough's initial
Team-2 ownership are Portal/Blockly compatibility choices, labeled separately
from game identity. Live network/playlist overrides and transition timing remain
outside the static importer; this is not a claim that every generated scene
already runs Andy's complete match logic.
Extra HQs are retained. Unsupported extra MCOM slots remain ObjId -1.

Missing geometry/endpoints and conflicting scalar bindings are listed in the
root's `bf6_import_warnings`. Plaza Rush has multiple authored targets for some
transition-area pins; the SDK scalar field stays null and the target identities
are retained as `bf6_unresolved_<property>`. No first-target or distance fallback.
Zero source polygon heights remain zero rather than inventing an extrusion.
Unresolved empty selections and missing required sector identities do not replace
an existing layout. They return an explicit build error.

## Reproduce

Run `tools/export_progressive_links.py --help` for the required research report
inputs. The addon includes the output, so users do not need the research repo.

Run `tests/test_exact_progressive.gd` headlessly in an initialized Portal SDK
test project with the addon installed and local layout files available. It checks
all 31 available nonempty layouts, expected sector/member identities, inspector
references, shared-node identity, scalar conflicts, scene serialization/reload,
the missing-sector refusal control, and Aftermath's seventh HQ. This is a data
and Godot-reference regression suite, not an in-game match comparison.

Validation on 2026-09-22: 31 layouts, 4,457 supported inspector links, zero
assertion failures and no engine warnings/errors in the initialized SDK harness.
Actor/spawn placement checks, scene save/reload, shuffled rows plus displaced
placements, and missing-sector preservation controls passed. The unrelated
Domination progress regression passed with 28 callbacks. Re-exporting the
derived link package produced an identical SHA-256. This build has not been
published or visually/playtested in a running match.

Follow-up validation on 2026-09-22: the export now resolves explicit attachment
endpoints across mode-partition boundaries. Fresh installed scans verified two
Abbasid and one Eastwood Breakthrough CaptureArea links to polygons stored in
conquest0. Only these referenced rows are added, with provenance; no Conquest
membership is copied. The headless suite now passes 4,460 inspector links and
328 uniquely owned authored-faction vehicle previews, across the same 31 layouts,
with zero assertions or engine warnings/errors. Runtime faction changes remain
distinct from these authored-default model selections.
